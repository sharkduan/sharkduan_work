
## Heavy Verification Policy

Heavy commands are opt-in/manual until Tasks 37-39 are implemented and source-verified. Missing heavy dependencies must not fail default CI.

## Heavy Test Marker Policy

- `lightweight` tests are default-CI tests and must not import heavyweight optional dependencies.
- `heavy` tests are opt-in and must be marked before dependency import.
- Heavy tests must distinguish dependency unavailable, platform unavailable, license unavailable, source verification missing, and runtime failure.
- Default CI may verify that heavy tests are discoverable, but it must not execute heavyweight dependency paths unless the `heavy` profile is selected.

## Mode Vocabulary

| Mode | Meaning |
| --- | --- |
| `lightweight` | default local/default-CI path; no hard import of RDKit, PyTorch, CUDA, PMDM, PocketFlow, docking, or network-only data |
| `heavy-manual` | opt-in environment with heavyweight dependencies and source verification |
| `local-data-manual` | user-provided local real data under `D:\codex_work\data`; readable only through manifest/checksum/license/provenance checks |
| `future-network-optional` | future optional source download capability only after explicit approval; not a v2-beta default path |
| `gpu-manual` | opt-in CUDA/GPU runtime path |
| `docs-only` | structured documentation or governance verification using `rg`/checklist evidence |
| `optional-research` | non-blocking research path that cannot gate v2-beta unless later promoted |
